SECTION 1: MAIN APPLICATION (app.py)
================================================================================

FILE: bulllens/app.py
PURPOSE: FastAPI application factory with startup/shutdown event handlers

KEY COMPONENTS:

1. IMPORTS & SETUP
   - FastAPI, CORSMiddleware, StaticFiles, Jinja2Templates
   - dotenv for environment configuration
   - bcrypt for password hashing
   - Custom database module

2. STARTUP FUNCTIONS

   async def provision_demo_account()
   ─────────────────────────────────
   - Auto-creates demo account on server startup
   - Username: demo, Password: demo1234 (environment configurable)
   - Uses bcrypt with 12 rounds for hashing
   - Checks if demo account already exists before creating

3. LIFESPAN CONTEXT MANAGER

   @asynccontextmanager
   async def lifespan(app: FastAPI)
   ────────────────────────────────
   - Runs init_db() on startup to initialize schema
   - Provisions demo account
   - Logs startup and shutdown events
   - Error handling with informative messages

4. APP FACTORY

   def create_app() -> FastAPI
   ──────────────────────────
   - Creates FastAPI instance with title, description, version
   - Configures CORS middleware (origins from .env)
   - Mounts static files directory
   - Registers routers:
     * auth_routes (prefix="")
     * stock_routes (prefix="/api")
     * ml_routes (prefix="/ml")

SECTION 2: DATABASE MODULE (database.py)
================================================================================

FILE: bulllens/database.py
PURPOSE: MySQL connection management and schema initialization

KEY FUNCTIONS:

1. get_db_config() -> dict
   ──────────────────────
   - Loads database credentials from .env
   - Returns dict with host, port, user, password, database
   - Sets charset to utf8mb4, collation utf8mb4_unicode_ci

2. get_connection() -> MySQLConnectionAbstract
   ───────────────────────────────────────────
   - Establishes new MySQL connection using get_db_config()
   - Uses mysql-connector-python library
   - Raises Error if connection fails

3. @contextmanager get_db_cursor(commit: bool = True)
   ──────────────────────────────────────────────────
   - Context manager for safe database operations
   - Auto-commits on success if commit=True
   - Auto-rollbacks on error
   - Returns cursor with dictionary=True (dict rows)

   USAGE:
   with get_db_cursor() as cursor:
       cursor.execute("SELECT * FROM users WHERE username = %s", (username,))
       rows = cursor.fetchall()

4. init_db() -> None
   ────────────────
   - Reads sql/schema.sql
   - Executes DDL statements to create tables
   - Called in FastAPI lifespan startup
   - Raises FileNotFoundError if schema.sql missing

SCHEMA CREATES:
- users table (user_id, username, email, password_hash)
- stocks table (stock_id, symbol, company_name, exchange)
- watchlist table (watchlist_id, user_id, stock_id, added_at)

FILE: bulllens/routes/auth_routes.py
PURPOSE: User authentication, registration, logout

KEY PYDANTIC MODELS:

1. LoginRequest
   ────────────
   - username: str
   - password: str

2. RegisterRequest
   ───────────────
   - username: str
   - email: str (validated with regex)
   - password: str

3. AuthResponse
   ────────────
   - status: str (ok/error)
   - username: str
   - user_id: int

HELPER FUNCTIONS:

1. get_user_by_username(username: str) -> dict | None
   ──────────────────────────────────────────────────
   - Queries users table by username
   - Returns dict with user_id, username, email, password_hash
   - Returns None if not found

2. hash_password(password: str) -> str
   ──────────────────────────────────
   - Uses bcrypt.hashpw with 12 rounds
   - Returns UTF-8 decoded hash string

3. verify_password(password: str, password_hash: str) -> bool
   ────────────────────────────────────────────────────────
   - Uses bcrypt.checkpw for comparison
   - Returns True if match, False otherwise

API ENDPOINTS:

1. POST /login
   ───────────
   - Request: LoginRequest (username, password)
   - Returns: AuthResponse
   - Sets session cookies:
     * session_user_id (httponly=True)
     * session_username (httponly=False)
   - Raises 401 if invalid credentials

2. POST /logout
   ────────────
   - Deletes session cookies
   - Returns {"status": "ok", "message": "Logged out"}

3. POST /register
   ───────────────
   - Request: RegisterRequest
   - Returns: user_id, username, message
   - Status Code: 201 Created
   - Raises 409 if username/email exists
   - Hashes password before storing

4. GET /me
   ────────
   - Requires session_username cookie
   - Returns: user_id, username, email
   - Raises 401 if not authenticated

SECTION 7: PRICE PREDICTION MODEL (ml_model/price_model.py)
================================================================================

FILE: bulllens/ml_model/price_model.py
PURPOSE: Linear Regression-based price prediction

KEY FUNCTION:

predict_price(symbol: str, horizon: int = 5) -> dict
──────────────────────────────────────────────────

PROCESS:
1. Normalizes symbol (adds .NS if needed)
2. Fetches 90 days of historical data from yfinance
3. Extracts close prices
4. Creates time-series features:
   - X: array of time indices (0, 1, 2, ..., n)
   - y: array of close prices
5. Trains LinearRegression model
6. Predicts price at (current_day + horizon)
7. Calculates 95% confidence interval

OUTPUT:
- predicted_price: float (ensured positive)
- confidence_interval: [lower_bound, upper_bound]
- model_used: "linear_regression"
- error: str (if failed)

EDGE CASES HANDLED:
- Insufficient data (< 30 days): returns error
- Negative predictions: returns error
- NaN predictions: returns error
- Positive check on confidence bounds

SECTION 8: VOLATILITY PREDICTION MODEL (ml_model/risk_model.py)
================================================================================

FILE: bulllens/ml_model/risk_model.py
PURPOSE: Random Forest volatility forecasting

KEY FUNCTIONS:

1. _artifact_path(horizon: int = 5) -> str
   ──────────────────────────────────────
   - Returns path to trained model file
   - Models stored per horizon: vol_model_h5.joblib, vol_model_h10.joblib, etc.

2. _load_training_df() -> pd.DataFrame
   ──────────────────────────────────
   - Reads archive/stocks_df.csv
   - Parses Date column to datetime

3. _features_from_df(df) -> tuple(df, list)
   ────────────────────────────────────────
   - Computes features from price data:
     * ret1, ret5, ret10: 1/5/10-day returns
     * mom5, mom10: 5/10-day momentum
     * vol5, vol10, vol20: 5/10/20-day rolling volatility
     * vchg: volume change
   - Returns augmented dataframe and list of feature names

4. _target_from_df(df, horizon) -> pd.Series
   ──────────────────────────────────────────
   - Computes target: forward-looking rolling volatility
   - Shifts returns forward and calculates rolling std

5. train_volatility_model(horizon=5, n_splits=5, random_state=42, 
                          n_estimators=500, max_depth=10) -> dict
   ─────────────────────────────────────────────────────────────
   HYPERPARAMETERS:
   - horizon: forecast horizon (days)
   - n_splits: time-series CV folds
   - random_state: reproducibility
   - n_estimators: trees in forest (500)
   - max_depth: max tree depth (10)

   PROCESS:
   1. Loads training data from archive/stocks_df.csv
   2. Computes features and target
   3. Splits data using TimeSeriesSplit (respects time order)
   4. Trains RandomForestRegressor with StandardScaler pipeline
   5. Calculates MAE on each fold using cross_val_score
   6. Refits on entire dataset
   7. Saves to ml/artifacts/vol_model_h{horizon}.joblib
   8. Returns mean/std MAE and other stats

6. predict_volatility(symbol: str, horizon: int = 5) -> dict
   ──────────────────────────────────────────────────────
   - Loads trained model for given horizon
   - Fetches recent price data for symbol
   - Computes features
   - Runs inference
   - Returns predicted_volatility, cv_score, unit

SECTION 17: KEY ARCHITECTURAL DECISIONS
================================================================================

1. FASTAPI CHOICE
   - Async-first, high performance
   - Built-in OpenAPI documentation
   - Excellent validation with Pydantic
   - Great for ML workloads

2. SESSION COOKIES
   - Browser session management (expires on close)
   - httponly flag for security
   - samesite=lax for CSRF protection
   - session_user_id only, session_username readable by JS

3. DATABASE CONTEXT MANAGER
   - Automatic connection cleanup
   - Rollback on error
   - Per-request isolation

4. TIMEZONE-AGNOSTIC
   - MySQL uses TIMESTAMP DEFAULT CURRENT_TIMESTAMP
   - Server timezone neutral

5. SEPARATE ML ARTIFACTS PER HORIZON
   - Models trained for different forecast horizons separately
   - Allows independent model management

6. LAZY-LOADED YOLO
   - Global singleton pattern
   - Downloaded on first request
   - Reduces startup time
